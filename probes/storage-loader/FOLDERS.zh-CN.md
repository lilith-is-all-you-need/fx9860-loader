# 文件夹 Loader 0.2

把 `FlashLd.g1a` 放在存储根目录，保留文件名。每个程序放在 `FXAPPS` 下的
独立目录，目录名为 1–8 个 ASCII 字母、数字或下划线；电脑端按名称加短 hash
生成。完整原始镜像为 `IMAGE.BIN`，384 字节 profile 为 `APP.FPF`，64 字节
元数据为 `APP.MET`，其中镜像大小必须与 profile 一致，否则在分配后端前拒绝。
可选 `ICON.BIN` 保存 G1A 文件偏移 `0x4C` 处的 30×17 单色图标。每行 4 字节，从最高位开始，行末两位补零，共 68 字节。
`RUN.LOG` 必须预分配 4096 字节，开头为 `FXFLASH1`。可选 `VERIFY.CCH` 同为
4096 字节，电脑端初始填零，计算器在完整内容校验后才写入有效缓存。

方向上下键选择，EXE 启动，EXIT 退出。F1 为完整校验，每次启动默认使用它；
F2 显示加速模式说明，再按 EXE 明确接受。每页两个图标，最多列出 32 个有效
目录，超出时显示上限提示；无效元数据会跳过。没有有效目录时兼容旧
`Loader.idx`。标记为超限的程序会显示，但普通 Loader 明确提示使用 EXT loader。

完整模式读取全文件、校验 SHA-256，并保存每页 FNV。加速模式要求已有缓存与
完整 profile、SHA、文件大小一致；缺失、损坏或过期时自动回退完整模式。
加速模式每次仍查询真实物理页，跳过的是首次全内容读取。缓存不保存历史物理
地址，因此两次启动之间即使页面移动也不会触发内容核对；只有本次运行后续
发现页地址变化才重新核对。**任何保持相同大小的 BIN 修改都可能漏检，
不限于相同物理位置。** 修改或替换
镜像后请用完整模式。缓存校验和只能发现损坏，不用于对抗恶意篡改。

日志格式为 `LOG_FORMAT=2`，读取到首次 `\nRUN_END\n` 即停止；其后的字节可能
属于旧运行。追加时覆盖前一个结束标记，省去原来 4 次各 1024 字节的清空写入。
`TICKS_VERIFY_RELEASE` 分别记录校验耗时和等待松开 EXE 的耗时；
`TICKS_MAP_READY` 分别记录第一次映射工作和选中后到最终验证映射的总耗时。
单位是原始系统 RTC tick，不是电脑计时。最终计时在清理退出时写入。
`READY_ENTRY` 不代表目标已经正常运行，落盘后仍有一次必须的物理映射刷新。

二进制协议的精确字段布局见同目录 `FOLDERS.en.md`，所有整数为大端。
本版本仍是实验性 GIII Flash 映射后端：不承诺任意 G1A 兼容，也不把模拟器
通过等同于实机稳定。它只保留自己的极小外壳、映射上下文和一个 OS RAM 字，
没有自动保存任意调用者的栈、堆、静态变量、句柄和设备状态。其他项目的
A→B→A 接入仍需要真实暂停/快照、冷启动恢复及明确的 MENU 策略；不支持嵌套。

## 原版 KhiCAS 的通用加载测试

2,094,444 字节的 khicasen.g1a 默认生成 Flash 目录。在固件辅助模拟器中（probe3 内存配置、Full 校验、FlashLd 摘要前缀 `02a2dd48`），直接启动原版能算出 `2+2 = 4`。同一镜像通过 FlashLd 启动时记录了 `READY_ENTRY`，随后在 `0x004F7A74` 遇到无效指令，未到输入界面。根因和实机表现待确认。复测时请在再次启动前保留 `FXAPPS/KH4A9D1C/RUN.LOG`。之前的 KLoad 实机记录对应手动选择的 mapped 适配器。
