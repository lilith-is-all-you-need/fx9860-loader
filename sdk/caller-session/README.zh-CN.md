# 调用方会话库

这是供 FxStudio 源码项目接入的 C99 库，协调单层 A 调用 B 时的**业务状态保存和恢复**。
它不搬运二进制、不保存 A 原来的栈与堆、不安装异常处理，也不会自动把当前
`FlashLd.g1a` 变成支持返回调用方的库。

本轮已经实现会话控制库和电脑侧故障测试；实际计算器后端仍须接管映射、入口、
退出和 MENU 恢复。后端及实机验收完成之前，不能把这里描述成“任意 A → B → A
已经打通”。当前 FlashLd 的能力不能据此提升。

## 接入源码项目

```cmake
add_subdirectory(path/to/sdk/caller-session caller-session)
target_link_libraries(my_addin PRIVATE FxStudio::CallerSession)
```

包含 `fx_caller_session.h`，提供暂停、序列化、重新初始化、恢复和继续运行回调，
以及经过验证的后端和工作缓冲区。库不申请堆、不直接调用 OS 或文件接口。
缓冲区大小为 96 字节头加业务数据，业务数据最多 65,536 字节。该缓冲区不意味着
在 B 运行时仍保留原 RAM；正式提交的快照由后端存到可靠的临时存储中。

`examples/caller_flow.c` 给出调用顺序，没有伪造 FlashLd 后端。后端尚未实现所需
能力时，`fxcs_prepare` 会在暂停 A、保存数据、写文件之前返回 `FXCS_UNSUPPORTED`。

## 已实现的会话流程

1. `fxcs_prepare` 检查能力和系统范围的调用深度，暂停 A，序列化业务数据，并
   事务化提交快照。调用方提供非零会话编号；后端拒绝重复编号，并原子占用唯一会话。
2. `fxcs_handoff` 交给 B。实机后端成功时通常不能再返回 A 的旧栈。异步后端可
   返回 `FXCS_TRANSFERRED`，此时 A 必须马上让出执行权，不能继续处理自己的业务。
   只有明确未发生交接且 A 的 RAM 仍完整时，才能报告交接失败并回滚。
3. B 正常退出且事件得到后端验证后，重新初始化 A，恢复业务快照，消费存储记录，
   再恢复 A 的活动资源。
4. MENU 后直接选回 A 时，`FXCS_MENU_RESTORE_CALLER` 要求后端结束 B 并恢复 A；
   `FXCS_MENU_RESUME_TARGET` 要求后端继续 B，保留 A 快照，直到 B 最后退出。
5. 确认进入过其他应用或者 OS 重启后，旧会话作废，不恢复 A 或 B。

“直接选回”必须来自常驻后端的可信生命周期记录，不能仅凭调用方传一个事件编号。
快照绑定启动编号、会话编号、调用方编号和业务数据版本。校验失败、身份不符、
生命周期不符时，库不会执行恢复回调，并保留记录以便诊断。CRC 只能发现意外损坏，
不是身份认证或数字签名。

尤其注意“继续 B”：后端必须在 A 的 CRT 改写 B 的 RAM 之前拦截入口，或者已经
完整保存并能恢复 B 所需的运行环境。仅仅让 A 重新初始化再读自己的业务快照，
做不到继续 B。同理，恢复 A 需要常驻跳板先恢复映射，再进入 A 的恢复入口；
不能从一个 C 函数直接返回已经被覆盖的旧内存。

## 后端必须兑现的约定

| 接口 | 要求 |
| --- | --- |
| `inspect` | 只读检查能力、启动身份、全局调用深度；拒绝重用会话编号 |
| `commit` | 原子持久化记录并占用唯一会话；失败不改变原有已提交内容 |
| `read` | 完整读取或者失败，不能静默截断 |
| `consume` | 比较完整会话身份后，只消费匹配记录；失败时保留记录 |
| `handoff` | 建立实际可兑现的目标生命周期；失败意味着 A 仍可安全继续 |
| `verify_event` | 核实启动/会话/前台应用连续性及调用方映射；恢复 A 前已停止 B 的资源 |
| `resume_target` | 恢复 B 的实际执行进度和运行环境，而不是重新运行 B 的 `main` |

第一版拒绝嵌套调用。检查深度和提交之间可能存在竞争，所以后端的提交也必须
原子抢占会话。后端回调表属于编译进源码的实现，不从 profile 执行任意插件。

原子存储由后端实现。一次普通文件写成功，不等于具备断电/中断后的事务保证。
可以采用预分配双记录、世代编号、校验和与提交标志，但必须验证中断写入和旧记录
选取。业务快照应保存可重建的数据，不能直接保存栈指针、OS 文件句柄、计时器
回调地址或分配器内部状态。

## 失败和重试

- 保存/提交失败时，不启动 B，恢复仍在内存中的 A。暂停回调若失败，须自行撤销
  已完成的部分暂停操作。
- 已准备好的调用可以取消。消费记录失败时 A 保持暂停，修复存储后重试
  `fxcs_cancel`，不能悄悄继续运行。
- 恢复失败时保留快照，可以在后端确认事件仍有效后重试。重新初始化/恢复回调
  必须幂等，不应重复向外部写入：恢复成功但消费记录失败，也会导致再次恢复。
- 继续 B 失败时仍保留 A 快照。常驻后端须提供安全错误出口；本库不能修复已损坏
  的 VBR、MMU 或目标栈。
- 运行其他应用或重启前，仍需常驻后端正确归还映射和资源；删除快照不等于清理。

## 验证范围

在仓库根目录运行：

```
python -m unittest discover -s tests -p test_caller_session.py -v
```

使用电脑 GCC/Clang 编译并运行九组生命周期测试，以及对 100 个快照字节逐个
注入损坏。覆盖两种 MENU 策略、清空调用方 RAM 后恢复、先拒绝再改状态、嵌套与
回调重入、保存/提交/交接/消费失败、恢复重试、跨启动拒绝和其他应用使会话作废。

也可在电脑 CMake 构建中启用 `FXCS_BUILD_HOST_TESTS`。以上为电脑侧接口与状态机
验证，没有证明计算器后端或实机状态恢复已经可用。详见 `VALIDATION.json`。
