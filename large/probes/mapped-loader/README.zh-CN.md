# KhiCAS 文件映射 Loader（实验版）

这是完整启动真实 KhiCAS 的专用链路。目标 BIN 与原 G1A 逐字节相同，
保留头部、代码、资源、CRT 和原入口 0x00300200；不是模拟输出的演示程序。
当前仅接受 SHA-256 为
`4a9d1c18009d987dc7c8745b7fc099b3c6e8006ebbb2ee5e4b483934be757473`
的 2,094,444 字节版本。没有声称支持多数 G1A，也没有完成本版实机验收。

## 运行方式

用 Fx Studio 原生 SDK 打开本目录，先 Debug 验证，再构建 Release。
用 Python 执行 `tools/prepare.py 原版.g1a 输出目录`。
将构建出的 G1A 命名为 **KLoad.g1a**，和生成的 **khicas.bin、
khicas.kpf、KLoad.txt** 一起放入计算器存储根目录；四个名称均需保留。
从菜单启动 KLoad，阅读 MENU 返回限制后按 EXE。先检查整个文件的 SHA-256，再查询映射和建立影子页，
进入 KhiCAS 原有启动界面后按 EXE 或选择其模式。

测试 2+2、2^10；按 MENU，选择另一个应用，随后重新打开 KLoad，
检查是否读回刚才的会话。再次切换应用后回传 KLoad.txt，并说明画面和操作。
EXIT 在 KhiCAS 内遵循 KhiCAS 的原有行为，并不强制退出整个应用。
用户已反馈首次启动可用，但 MENU 后直接选回 KLoad 停在疑似 Loading。
模拟器尚未复现这个实机问题；不能视为已经修复。可额外按一次 EXE 观察，
需要重新启动时先进入 RUN-MAT 再打开 KLoad。本版启动页会明确提示。
KLoad.txt 保存**最近一次启动**，每次启动重新写入；需要比较两轮时先复制上轮。
KhiCAS 会按原行为读取/写入 session.xw、FMENU.cfg，已有会话需要保留时先备份。

## 机制和内存代价

- 解析并校验已核对的 OS 映射函数指纹；借用 OS 的 512 项页表和缺页补填机制。
  Loader 的执行桥、上下文和路径放在映射窗口之外。文件页不要求物理连续。
- 只复制第 0、465、470、471 页到 RAM，修改 51 个已分类的 syscall 网关常量，
  以及 main 中 3 个内存池初始化常量；文件本体不改。
- 原工作区 0x88051000/0x88052000 改为 0x88060000/0x88061000；
  arena 起点 0x88053800 改为 0x88062800，上界保持 0x8807D000。
  arena 从 166 KiB 缩为 106 KiB，减少 60 KiB。大型计算可能更早内存不足。
- Loader 一次分配约 40 KiB，包括 16 KiB 影子页、上下文、驻留代码和对齐空隙；
  启动时检查实际分配末端，越界拒绝运行。文件 SHA 缓冲的栈帧在交接前释放。
- 仍执行真实 CRT、main 和注册的退出回调。拦截 SetQuitHandler 和 Timer_Install，
  保留驻留退出桥；文件操作、GetKey 返回、菜单退出前重新查询 BIN 与 Loader
  自身的文件页地址，并验证变化页的内容。未知查询错误拒绝继续执行并留档重启。
- 每个 syscall 桥保留原调用参数，包含 8 个栈参数及实际 OS 返回的 r0..r7、SR、MACH/MACL；
  不依赖 LLM，也不在缺页处理中打开文件。

## 边界

转换器是确定性的精确版本适配器。现有证据来自二进制调用位置、初始化流程、
相关历史源码的辅助对照、已有 Probe3 实机证据和本版模拟器验证。
Probe3 验证了底层机制；不等于这个新 Loader 已在实机上验证。

“多数 G1A 无人干预”需要定义代表性样本和成功标准，逐个程序家族建立可复用规则，
自动核对指纹、调用和内存约束，遇到未知情况明确拒绝。Ghidra/脚本足以作为
自动化流水线的工具，LLM 不应成为转换和加载的运行时依赖；它也不能提供覆盖率保证。

模拟器的文件映射压力模式能制造碎片和写操作后的页表恢复，尚未重现真正的
Flash 整理、完整 copy-back 数据缓存和任意中断嵌套。基本计算、会话保存和菜单
回调通过，只说明这些路径通过，不能证明 KhiCAS 全部算法、图形和外设功能。
尤其是复杂计算时的计时器回调、实机剩余 OS 堆、长时间运行仍需继续验收。
